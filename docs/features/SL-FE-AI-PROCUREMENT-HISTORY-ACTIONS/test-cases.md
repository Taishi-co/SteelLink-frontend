# AI采购历史操作按钮 Test Cases

## 测试范围

- Feature ID: SL-FE-AI-PROCUREMENT-HISTORY-ACTIONS
- 测试负责人: Codex

## Happy Path

| 编号 | 场景 | 前置条件 | 步骤 | 期望结果 |
| --- | --- | --- | --- | --- |
| TC-01 | 再买一次 | 买家已登录且存在 AI采购历史记录 | 进入 `/ai-procurement`，点击某条历史记录的“再买一次” | 页面停留 AI采购首页，采购对话框填入该记录 `prompt`，用户可重新解析 |
| TC-02 | 查看详情 | 买家已登录且存在 AI采购历史记录 | 点击某条历史记录的“查看详情” | 页面进入 `/ai-procurement/6`，展示该历史采购详情 |
| TC-03 | 复制采购对话 | 买家已登录且存在 AI采购历史记录 | 点击某条历史记录的“复制” | 剪贴板写入该记录 `prompt`，页面显示复制成功提示 |

## Exception Path

| 编号 | 场景 | 前置条件 | 步骤 | 期望结果 |
| --- | --- | --- | --- | --- |
| TC-EX-01 | 剪贴板不可用 | 浏览器阻止 Clipboard API | 点击“复制” | 使用兼容复制逻辑；若仍失败，显示复制失败提示，不影响列表 |

| 编号 | 角色 | 场景 | 期望结果 |

## 回归关注点

- AI采购解析、商品匹配、物流仓储匹配、订单生成和提交审核步骤不受历史操作按钮影响。
- 历史列表刷新仍调用原有 `listMine` 逻辑。
