# Feature Spec

## 基本信息

- Feature ID: `SL-FE-WORKBENCH-FLOW-BASELINE`
- Feature 名称: 五个工作台流程状态基线校准
- 负责人: Codex
- 目标上线环境: 本地开发 / 测试联调环境

## 背景

当前买家、卖家、仓储、物流、资金方五个工作台已经接入主要订单与履约流程，但部分页面仍保留旧版订单状态口径，导致同一订单在不同工作台展示不一致。例如后端 `21` 已是已归档，资金方工作台仍展示为融资审批中；买家订单列表的当前动作也把 `21/22` 向前错位。

本轮目标是先建立前端流程基线，让五个工作台按后端 `OrderStatus` 枚举展示一致的状态和下一步动作，为后续拆分大页面、权限收口和接口补齐打基础。

## 范围

### In Scope

- 校准买家工作台订单概览、订单列表、订单详情中的订单状态文案。
- 校准卖家工作台订单状态映射中缺失的待选择仓库状态。
- 校准仓储工作台订单状态映射中缺失的待签署物流合同状态。
- 校准资金方工作台订单状态映射，修正融资、物流、归档状态错位。
- 保留现有 API 调用与页面结构，不新增业务能力。

### Out of Scope

- 不重构五个工作台的大页面结构。
- 不新增收藏、通知、权限管理等接口能力。
- 不调整跨应用 token 传递方式。
- 不修改后端订单状态机。

## 页面与交互影响

- 受影响页面:
  - 买家工作台：`Dashboard/Overview`、`Orders`、`OrderDetail`
  - 卖家工作台：`Orders`
  - 仓储工作台：`App`
  - 资金方工作台：`App`
  - 物流工作台：无订单数值状态映射改动，本轮仅纳入流程核对范围
- 受影响路由:
  - `/dashboard`
  - `/orders`
  - `/orders/:id`
  - 资金方、仓储方、卖家方工作台内 tab
- 受影响布局或导航: 无
- 受影响组件: 状态 Tag、订单列表当前动作文案
- 受影响交互状态: 无新增交互

## 接口与数据影响

- 受影响接口: 无
- 请求参数或响应结构变化: 无
- 受影响服务层: 无
- 受影响状态管理: 无
- 受影响后端 handler/service/repository: 无
- 受影响数据库或缓存: 无
- 配置或环境变量变化: 无
- 构建或部署影响: 无

## 权限与合规影响

- 受影响角色: 买家、卖家、仓储服务商、资金方
- 新增/调整权限: 无
- 是否影响审核、风控、日志留痕: 不影响，仅校准前端展示口径

## 验收标准

1. 买家、卖家、仓储、资金方工作台对 `20/21/22/23/24/25/26/27` 的展示与后端 `OrderStatus` 一致。
2. 买家订单列表中 `21` 展示为已归档，`22` 展示为融资审批中，`23` 展示为请签署融资合同。
3. 资金方工作台不再把 `21` 当作融资审批中，不再把 `20` 当作已归档。
4. 买家详情页能正确区分待重新选仓、待重新发起物流、待选择仓库和待签署物流合同。
