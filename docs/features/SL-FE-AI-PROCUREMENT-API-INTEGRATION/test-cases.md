# Test Cases

## 测试范围

- Feature ID: SL-FE-AI-PROCUREMENT-API-INTEGRATION
- 测试负责人: Codex

## Happy Path

| 编号 | 场景 | 前置条件 | 步骤 | 期望结果 |
| --- | --- | --- | --- | --- |
| TC-01 | 未输入时查看页面 | 任意用户 | 打开 `/ai-procurement` | 不展示假采购结果，显示空状态 |
| TC-02 | 解析采购需求 | 已登录 | 输入采购需求并点击解析 | 调用 `/ai-procurements/parse` 并展示真实返回 |
| TC-03 | 创建 AI采购单 | 已登录且输入采购需求 | 点击发起 AI采购或生成采购单 | 调用 `/ai-procurements`，返回采购单并刷新我的 AI采购 |
| TC-04 | 查看我的采购 | 已登录且有采购单 | 点击我的 AI采购记录 | 页面展示该记录的真实流程数据 |
| TC-05 | 提交审核 | 已创建采购单且有匹配结果 | 点击提交审核 | 调用提交审核接口并更新审核状态 |

## Exception Path

| 编号 | 场景 | 前置条件 | 步骤 | 期望结果 |
| --- | --- | --- | --- | --- |
| TC-EX-01 | 未登录解析 | 未登录 | 点击解析 | 提示先登录，不调用接口 |
| TC-EX-02 | 空指令解析 | 已登录 | 不输入内容点击解析 | 提示输入采购需求 |
| TC-EX-03 | 非企业账号创建 | 已登录但无企业 ID | 发起 AI采购 | 展示创建失败提示 |
| TC-EX-04 | 无采购单提交审核 | 已登录但未创建采购单 | 点击提交审核 | 提示先创建采购单 |

## 权限测试

| 编号 | 角色 | 场景 | 期望结果 |
| --- | --- | --- | --- |
| TC-AUTH-01 | 游客 | 访问页面 | 可访问说明和输入区 |
| TC-AUTH-02 | 游客 | 解析/创建 | 被前端拦截并提示登录 |
| TC-AUTH-03 | 买家用户 | 查看我的采购 | 可访问自己的采购单 |

## 回归关注点

- 现货商城、供求信息、订单等页面不受影响。
- API 401 仍应走现有登录跳转逻辑。
