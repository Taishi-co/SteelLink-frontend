# 物流履约责任流观测

## 背景

当前买卖家对物流的观测主要来自订单状态与 `shipment_task` 四步进度，无法表达仓储预约、到场签到、出库确认、装货确认等重工业履约节点。

后端将把物流细状态沉淀到独立的 `service-fulfillment` 摘要中，前端需要以此作为买卖家观测入口，同时不改动订单主流程页面的交易状态语义。

## 目标

1. 买家订单详情展示独立物流履约责任流。
2. 卖家订单详情或履约页展示同一套责任流摘要。
3. 物流端状态文案同步升级为细粒度履约节点。
4. 保留旧 `shipment_task` 兼容展示，但优先展示新履约摘要。

## 非目标

- 不重做买家/卖家订单页整体结构。
- 不引入新的独立买家或卖家物流工作台。
- 不删除旧 `shipment_task` 视图。

## 交互要求

### 买家端

- 在订单详情中展示“当前责任主体”“当前履约节点”“关键节点时间”
- 履约步骤按独立物流状态展示
- 如存在轨迹事件，按时间线展示

### 卖家端

- 在订单详情中展示与买家一致的履约摘要
- 履约核销页保留原功能，但增加对独立物流状态的观测字段

### 物流端

- 状态按钮与文案切换为细粒度节点
- 物流订单列表可直接看到当前责任主体

## 兼容要求

1. 老订单如果只有 `shipment_task`，页面仍可展示旧四步流程。
2. 新老物流状态同时存在时，前端优先使用 `service-fulfillment.logistics_orders[0]`。
