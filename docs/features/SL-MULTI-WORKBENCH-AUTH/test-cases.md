# 多工作台会话切换测试用例

## 测试范围

- Feature ID: SL-MULTI-WORKBENCH-AUTH
- 测试负责人: Codex

## Happy Path

| 编号 | 场景 | 前置条件 | 步骤 | 期望结果 |
| --- | --- | --- | --- | --- |
| TC-01 | 买家端进入物流工作台 | 企业已开通 `logistics` 服务能力 | 从个人工作台点击进入物流管理中心 | 前端创建 `switch_token`，物流端消费后保存 `logistics_token`，页面可请求数据 |
| TC-02 | 买家端进入仓储工作台 | 企业已开通 `warehouse` 服务能力 | 从服务入口点击仓储资源管理 | 仓储端消费 `switch_token` 后进入 `resources` tab |
| TC-03 | 买家端进入资金方工作台 | 企业已开通 `finance` 服务能力 | 从个人工作台点击进入资金方工作台 | 资金方工作台获取新 token，不出现 `token expired` |
| TC-04 | 买家端进入卖家中心 | 企业已开通 `sales` 服务能力 | 点击进入卖家中心或竞价大厅参与报价 | 卖家端消费 `switch_token` 后进入目标页面 |
| TC-05 | 卖家端返回买家工作台 | 企业已开通 `procurement` 或企业角色为买方 | 点击返回买家工作台 | 买家端消费 `switch_token` 后进入个人工作台 |

## Exception Path

| 编号 | 场景 | 前置条件 | 步骤 | 期望结果 |
| --- | --- | --- | --- | --- |
| TC-EX-01 | 目标工作台残留过期 token | 本地存在过期 `logistics_token`，存在有效 `buyer_token` | 进入物流工作台 | 过期 token 被清理，不再向后端发送 |
| TC-EX-02 | 切换凭证过期或无效 | `switch_token` 已被消费或超过 TTL | 打开带 `switch_token` 的目标工作台 | 页面提示切换失败，并保留共享 token 兜底逻辑 |

## 权限测试

| 编号 | 角色 | 场景 | 期望结果 |
| --- | --- | --- | --- |
| TC-AUTH-01 | 企业仅开通采购能力 | 访问物流/仓储/资金方入口 | 不展示未授权工作台入口 |
| TC-AUTH-02 | 企业角色为资金方但额外开通销售能力 | 访问卖家工作台 | 可通过 `sales` 能力进入卖家工作台 |
| TC-AUTH-03 | 企业角色为卖方但额外开通物流能力 | 访问物流工作台 | 可通过 `logistics` 能力进入物流工作台 |

## 回归关注点

- 买家端登录、卖家端登录、目标工作台直接刷新。
- `X-Token-Refreshed` 后前端保存新 token 的行为。
- 服务能力列表为空时的企业角色兜底展示。
