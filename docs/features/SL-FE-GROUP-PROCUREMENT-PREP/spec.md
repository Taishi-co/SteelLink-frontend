# Feature Spec

## 基本信息

- Feature ID: SL-FE-GROUP-PROCUREMENT-PREP
- Feature 名称: 集采大厅前端规划筹备
- 负责人: Codex
- 目标上线环境: buyer-app

## 背景

买家端已有“集采大厅”导航，但当前仍是占位页。集采大厅应首先是多个集采活动的聚合入口，而不是单个活动详情页；在大厅中选中活动后，再展示该活动的牵头方筹备工作台和完整业务流。

## 范围

### In Scope

- 替换 `/procurement` 占位页。
- 展示集采大厅汇总指标、筛选条件和多个集采活动卡片。
- 活动卡片展示编号、牵头方、品类、目标数量、预算、阶段、参采企业、报价数量和进度。
- 展示九阶段流程：集采筹备、企业报名、竞价报价、评审定标、合同签约、履约备货、货款结算、成交归档、售后评价。
- 展示牵头方和平台运营角色元素。
- 展示选中活动的基础信息、实时数据、全流程进度、第一阶段筹备子流程。
- 提供牵头方集采需求表单、资质文件上传入口、AI需求校验入口、集采预览和活动日志。

### Out of Scope

- 不新增后端 API。
- 不保存表单数据。
- 不实现真实文件上传。
- 不实现后续八个阶段的业务提交。

## 交互与页面影响

- 受影响页面: `/procurement`
- 新增页面: `apps/buyer-app/src/pages/Procurement/index.tsx`
- 路由变化: `/procurement` 从占位页替换为集采大厅页面。
- 菜单变化: 无。

## 数据与接口影响

- 受影响 API: 无。
- 请求/响应变化: 无。
- 环境变量变化: 无。

## 权限影响

- 当前筹备页公开可访问。
- 后续接真实发起、审核、报名、报价时应区分牵头方、平台运营、参采企业、供应商权限。

## 验收标准

1. `/procurement` 首屏展示集采大厅，而不是单个活动详情。
2. 大厅包含多个集采活动卡片和筛选入口。
3. 页面包含九阶段集采流程。
4. 页面包含“2024年第一季度电解铜联合采购”作为选中活动工作台。
5. 页面包含第一阶段“集采筹备与发起”的三步子流程。
6. 页面包含牵头方可操作的集采需求表单。
7. 页面包含集采预览和活动日志。
